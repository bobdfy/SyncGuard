  • RunJob 事务边界（L215-230）：Begin → Outbox.Insert(tx,payload) → Commit，defer Rollback 兜底。HTTP 只负责把"待发消息"原子落库，真正发 MQ 由文件35 dispatcher 异步完成——这是事务性 Outbox 模式的前端落点，进程崩溃也不丢任务。
  • RunJob 不直接调 MQ.Publish，而是写 outbox（DelayMs=0），实现了与文件36 Worker 的解耦；attempt 从 0 开始。
  • CreateJob 双重归属校验（L80-101）：源 connection 必须属于当前用户；若填了目标 connection，同样校验归属，否则 403；未填目标表示写内部存储。
  • Reconcile（L278-319）验权后把 connectionID、userID、syncContent 传给 reconciliation.Reconciler（文件37），返回 difference_count 与差异列表。
  • ListRecords（L238-269）用 limit/offset 分页（默认 50/0），按 userID 查 synced_records。
  • 所有方法的鉴权统一靠 c.Get("userID") + 查库后比对 job.UserID/conn.UserID，与 connection.go 一致的多租户模式。
